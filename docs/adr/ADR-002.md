# ADR-002: Participant 중간 도메인 분리 이유

- Status: Accepted
- Context: 한 사용자는 여러 약속방에 참여하고 한 약속방에는 여러 사용자가 참여한다. 방별 역할과 참여 시점도 필요하다.
- Decision: User와 MeetingRoom을 직접 N:M으로 연결하지 않고 `Participant`를 명시적 중간 도메인으로 둔다. HOST의 유일한 source of truth는 `Participant.role`이다.
- Alternatives: JPA `@ManyToMany`, `MeetingRoom.hostId`와 Participant 역할의 이중 관리.
- Consequences: 조인 엔티티가 하나 늘지만 역할·가입시점·접근권한·중복참여 제약을 명확히 관리한다.
- Verification: `UNIQUE(meeting_room_id, user_id)`, Meeting 생성과 HOST Participant 생성의 단일 트랜잭션 테스트.
