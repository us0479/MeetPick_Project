# ADR-010: Nginx Reverse Proxy 배포 구조 선택 이유

- Status: Accepted
- Context: 하나의 웹 URL에서 React 정적 파일과 Spring API를 제공하고 SPA refresh 404/CORS/HTTPS 문제를 단순화해야 한다.
- Decision: Nginx가 React build 정적 파일을 서빙하고 `/api`와 health 요청을 Spring Boot로 reverse proxy한다. 운영에서는 HTTPS termination을 Nginx/상위 로드밸런서 계층에 둔다.
- Alternatives: 프론트/백엔드 별도 origin 직접 노출, Spring에서 정적 파일 동시 서빙.
- Consequences: 배포 계층이 하나 늘지만 same-origin API, SPA fallback, TLS/헤더 처리를 중앙화한다.
- Verification: `/api` proxy, `/actuator/health`, React route 직접 refresh, HTTPS forwarded header 확인.
