# ADR-009: QueryDSL 동적 조회 구조 선택 이유

- Status: Accepted
- Context: 내 약속방 목록은 status, 날짜 범위, pagination 등 조건 조합이 필요하고 B의 SQL/Index 실험 대상이다.
- Decision: 단순 CRUD는 Spring Data JPA를 사용하고 조건 조합이 필요한 목록 조회는 QueryDSL custom repository로 분리한다.
- Alternatives: 메서드명 파생 쿼리 다수, Criteria API, 문자열 JPQL.
- Consequences: 타입 안전성과 조건 조합 가독성이 좋아지나 Q-type 생성과 custom repository 구조가 필요하다.
- Verification: 조건 조합 Repository 테스트, SQL query 수, N+1 재현/개선, EXPLAIN ANALYZE 전후 측정. `user_id`는 Participant, `status/candidate_start_at`은 MeetingRoom 컬럼이므로 세 컬럼을 한 복합 인덱스로 묶지 않는다. 각 테이블의 인덱스 후보를 별도로 비교한다.
