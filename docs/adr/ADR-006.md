# ADR-006: 확정 후 알림을 Transaction Event로 분리한 이유

- Status: Accepted
- Context: Confirm이 rollback됐는데 Notification이 남아서는 안 되고, 핵심 트랜잭션과 후속 부수효과를 분리할 필요가 있다.
- Decision: Confirm 성공 시 domain event를 발행하고 `@TransactionalEventListener(AFTER_COMMIT)`에서 `REQUIRES_NEW` 트랜잭션으로 Notification을 저장한다.
- Alternatives: Confirm Service 내부 직접 저장, 일반 `@EventListener`, 외부 메시지 브로커.
- Consequences: 핵심 확정과 알림 저장이 분리된다. AFTER_COMMIT 이후 알림 저장 실패는 별도 재처리 전략이 향후 과제로 남는다.
- Verification: Confirm 중 예외 발생 시 Meeting 미확정 + Notification 0건, commit 성공 시 참여자 알림 생성.
