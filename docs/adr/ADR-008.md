# ADR-008: 공통 ApiResponse/ErrorResponse 구조 선택 이유

- Status: Accepted
- Context: 3명이 각 도메인 API를 구현하므로 성공/실패 payload와 HTTP status를 통일하지 않으면 프론트와 예외처리가 분산된다.
- Decision: 성공은 `{success:true,data}`, 실패는 `{success:false,error:{code,message}}`로 통일하고 `ErrorCode + BusinessException + GlobalExceptionHandler`를 사용한다.
- Alternatives: Controller별 자유 응답, HTTP status만 사용.
- Consequences: 프론트 처리와 API 문서가 단순해지지만 모든 팀원이 공통 예외 규칙을 따라야 한다.
- Verification: ErrorCode 중복 방지 테스트, validation/business/unexpected error 응답 테스트.
